# Тайна затерянного мира

Кооперативная 2D-браузерная игра для детского мероприятия: 3–4 игрока, у каждого свой телефон, один общий мир с видом сверху. Запускается по ссылке, регистрация и установка не нужны.

Это **стартовый прототип**: общая комната, персонажи, перемещение и синхронизация. Задания (разделённые подсказки, одновременные действия, артефакты, голосование, сборка) будут добавлены поверх этой основы, см. [docs/TECHNICAL_SPEC.md](docs/TECHNICAL_SPEC.md).

## Что уже работает

- Стартовый экран: имя, «Создать комнату», «Подключиться» по коду из 6 символов.
- Анонимная авторизация Supabase (id игрока = id анонимного пользователя).
- Комнаты до 4 игроков. Понятные сообщения, если комната не найдена или заполнена.
- Общий мир 2400×1600 с камерой, границами, деревьями, дорожками, руинами и порталом.
- Игроки видят друг друга: цветные персонажи с именами. Локальный персонаж подсвечен.
- Синхронизация: Presence (кто в комнате) и Broadcast (координаты, ~12 раз в секунду) с плавной интерполяцией.
- Управление: экранный джойстик (touch/pointer) и WASD / стрелки. Сброс ввода при потере фокуса.
- Обработка обрывов связи: статус на экране, автоматическое переподключение, без дублей персонажей.
- Кнопка «Выйти» (с подтверждением), тёмная фэнтези-тема, safe-area, подсказка «Поверните телефон».
- Публикация на GitHub Pages через GitHub Actions.

## Стек

TypeScript, Phaser 3, Vite, HTML/CSS, Supabase (Anonymous Auth, Realtime Presence + Broadcast), GitHub Pages. Других зависимостей нет.

## Быстрый старт

Нужен Node.js 20 или новее.

```bash
npm install
cp .env.example .env      # Windows PowerShell: Copy-Item .env.example .env
# заполните VITE_SUPABASE_URL и VITE_SUPABASE_ANON_KEY (см. раздел ниже)
npm run dev
```

Откройте http://localhost:5173.

Другие команды:

| Команда | Что делает |
| --- | --- |
| `npm run dev` | локальный сервер с горячей перезагрузкой (доступен по сети) |
| `npm run build` | проверка TypeScript и сборка в `dist/` |
| `npm run typecheck` | только проверка типов |
| `npm run preview` | предпросмотр собранной версии |

### Режим демо без Supabase (только для разработки)

Чтобы посмотреть мир и управление, не настраивая сервер, откройте в dev-режиме
`http://localhost:5173/?demo=1`. Вы окажетесь в комнате `DEMO42` с двумя ботами.
Параметр `?touch=1` принудительно показывает экранный джойстик на компьютере.
В production-сборку демо-режим не попадает.

## Настройка Supabase (обязательно один раз)

Подробно: [docs/SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md). Коротко:

1. Создайте проект на https://supabase.com.
2. **Authentication → Sign In / Providers**: включите **Allow anonymous sign-ins**.
3. **Project Settings → API**: скопируйте `Project URL` и ключ `anon` / `publishable`.
4. Вставьте их в `.env`:
   ```env
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJ...
   ```
5. Таблицы и SQL-миграции **не нужны**: комнаты работают на Realtime Presence/Broadcast.

Ключ `service_role` во frontend использовать нельзя: он даёт полный доступ к базе.

## Как проверить мультиплеер

**На одном компьютере.** Откройте 2–4 вкладки с `http://localhost:5173`. Сессия хранится в `sessionStorage`, поэтому каждая вкладка это отдельный анонимный игрок. В первой нажмите «Создать комнату», в остальных введите код.

**На телефонах.** Телефоны и компьютер должны быть в одной Wi-Fi сети. `npm run dev` печатает адрес вида `http://192.168.x.x:5173`. Откройте его на телефонах. Если Windows Firewall спрашивает разрешение для Node.js, разрешите доступ для частных сетей. Для опубликованной версии (HTTPS) ничего дополнительно настраивать не нужно.

**Чек-лист приёмки**

- [ ] `npm install` и `npm run build` проходят без ошибок.
- [ ] Игрок 1 создаёт комнату, код виден в левом верхнем углу.
- [ ] Игроки 2, 3, 4 подключаются по коду, все видят друг друга и имена.
- [ ] Игрок 5 получает сообщение «Комната заполнена».
- [ ] Ввод несуществующего кода даёт «Комната … не найдена».
- [ ] Движение одного игрока плавно видно у остальных, дублей персонажей нет.
- [ ] Закрытие вкладки или «Выйти»: персонаж пропадает у остальных, из списка тоже.
- [ ] Отключение Wi-Fi на несколько секунд: появляется плашка «Связь потеряна…», после возврата сети игрок на месте и без дубля.
- [ ] На телефоне в альбомной ориентации джойстик работает, страница не прокручивается. В портретной видна подсказка повернуть устройство.

## Как устроена синхронизация

- **Presence** хранит состав комнаты: имя, цвет, порядок входа. Это единственный источник правды о том, кто в комнате. Ключ записи = id пользователя Supabase, поэтому дубликатов нет.
- **Broadcast `pos`** передаёт координаты не чаще ~12 раз в секунду и только при изменении (плюс редкое повторение для надёжности).
- Локальный персонаж двигается сразу, без ожидания сети. Удалённые плавно догоняют полученные координаты.
- **Лимит 4 игроков.** Игроки упорядочены по паре `(joinedAt, id)`, видимыми считаются только первые четыре. Если пятый всё же успел войти (гонка), он сам выходит с сообщением, а у остальных не появляется.
- **Переподключение.** При обрыве показывается плашка, канал пересоздаётся с нарастающей паузой, после восстановления игрок снова объявляется в Presence, а список игроков обновляется.

## Публикация на GitHub Pages

Подробно: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). Коротко:

1. Создайте репозиторий на GitHub и отправьте код в ветку `main`.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. **Settings → Secrets and variables → Actions → вкладка Variables → New repository variable**: добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Это именно Variables, а не Secrets: ключ `anon` публичный по своей природе и всё равно попадает в браузер.
4. Сделайте push в `main`. Workflow `Deploy to GitHub Pages` соберёт проект и опубликует `dist/`.
5. Игра будет доступна по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`.

Base path (`/<имя-репозитория>/`) workflow подставляет сам. Если используете свой домен или репозиторий `<логин>.github.io`, задайте `VITE_BASE_PATH=/`.

## Ограничения прототипа (важно)

Безопасность в этой версии не рассчитана на публичный запуск:

- Канал комнаты публичный: любой, кто знает код (или подберёт его), может подключиться или отправлять сообщения.
- Лимит 4 игроков и проверка существования комнаты выполняются **на клиентах**, сервер их не гарантирует.
- Комната существует, пока в ней есть хотя бы один игрок. Если все вышли, код перестаёт работать.
- Если у единственного игрока в комнате пропала связь, а другой в этот момент пытается войти, он может получить «комната не найдена». Повторите попытку.
- Лимиты Supabase на анонимные входы (по умолчанию 30 в час с одного IP) могут помешать, если на одной Wi-Fi сети много тестовых запусков. См. [docs/SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md).

План перехода к защищённой версии (таблицы комнат, RLS, приватные каналы, серверная проверка действий) описан в [docs/SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md).

## Частые проблемы

| Симптом | Причина и решение |
| --- | --- |
| «Не настроен Supabase…» | Нет `.env` или он пустой. После правки `.env` перезапустите `npm run dev`. |
| «Выключена анонимная авторизация» | Включите Allow anonymous sign-ins в Supabase. |
| «Сервер не отвечает» | Проверьте URL проекта, интернет, что проект Supabase не на паузе. |
| Игроки не видят друг друга | Проверьте, что Realtime включён и публичный доступ к каналам разрешён (см. SUPABASE_SETUP). |
| После публикации белый экран / 404 на ресурсы | Неверный base path. Проверьте, что сборка шла через workflow (`VITE_BASE_PATH`). |
| С телефона не открывается dev-адрес | Разные сети, либо Firewall блокирует порт 5173. |
