# Разработка квеста

## Рабочий процесс

1. Определить затронутые файлы.
2. Изучить только нужные участки.
3. Составить краткий план изменений.
4. Реализовать задачу небольшими логическими блоками.
5. Проверить взаимодействие с существующими модулями.
6. Проверить TypeScript и сборку.
7. Кратко сообщить результат.

Не проводить повторный анализ всего проекта при каждом использовании этого Skill.

## Новые игровые механики

При разработке новых игровых механик всегда учитывать:

- одновременную работу 3–4 игроков;
- синхронизацию игрового состояния;
- восстановление состояния при переподключении;
- мобильное управление;
- отсутствие дублирования игровых объектов;
- одинаковый результат для всех участников комнаты.

## Опорные модули (читать по необходимости)

| Область | Где смотреть |
|--------|----------------|
| Сеть, комнаты, broadcast | `src/network/realtimeService.ts`, `src/network/types.ts` |
| Мост UI ↔ игра | `GameBridge` в `types.ts`, registry в `WorldScene` |
| Мир и параметры | `src/game/config/worldConfig.ts`, `src/game/world/WorldBuilder.ts` |
| Игроки, интерполяция | `src/game/entities/Player.ts` |
| Частота отправки | `src/config/appConfig.ts` |
| Мобильный ввод | `src/ui/MobileControls.ts` |

Следовать постоянным правилам проекта в `.cursor/rules/quest-project.mdc`.
